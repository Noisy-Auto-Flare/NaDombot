# Ожидаемый результат: как это будет выглядеть и работать (ревью)

**Статус:** эталон приёмки. Ничего из этого ещё не собрано до конца — это то, что мы
проверяем в конце на тестовом стенде.
**Скоуп сейчас:** только 10А (шаг выбора класса пропускается автоматически).
**Задел на будущее:** выбор из нескольких классов (6А/6Б/…, 10А/10Б) уже заложен —
шаг появится сам, когда включённых классов станет ≥2. Код под это уже есть
(`getAvailableClasses`, пропуск пустых осей).
Связанные файлы: `docs/architecture-old.md` (было), `docs/architecture-new.md` (как строим).

## A. СЛОВАМИ — что видит человек (пошагово)

### A1. Первый вход (флаг ВКЛ, профиля нет). Пример: ученик тех-профиля у Беловой

1. `/start` → вместо меню сразу онбординг: «👋 Выберите профиль:»
   `[🔬 Технологический] [💼 Социально-экономический] [👀 Видеть всё]`
   (шага класса нет — класс один, 10А подставлен молча).
2. Жмёт «Технологический» → «У кого английский?»
   `[Белова (каб. 4005)] [Петрова (библ)] [👀 Видеть всё]`.
3. Жмёт «Белова» → «✅ Профиль сохранён: 10А · Технологический · Белова» → главное меню.
4. В меню сверху строка `👤 10А · Технологический · Белова` + кнопка `👤 Профиль`.

Альтернатива на шаге 1/2 — «👀 Видеть всё»: онбординг завершается сразу,
остальные поля пустые, дальше — merged-view всего 10А.

### A2. Просмотр домашки (профиль `10А / tech / belova`), понедельник

`📅 Домашнее задание на завтра` (понедельник):
```
📅 Понедельник, 05.10
1. Разговор о важном — каб. 2035
   ✅ Нет домашнего задания
2. Информатика — каб. 1058
   📝 ...
5. Информатика — каб. 1058 ...
6. Биология — каб. 3026 ...
7. Геометрия — ...
```
Чего здесь НЕТ: `Обществознание` (это soc-строки того же слота) и английского Петровой.
Ученик `soc + petrova` в тех же слотах увидит `Обществознание` и `Английский, библ`.
Оба увидят `Биологию`, `Алгебру`, `Разговор о важном` — общие уроки.

### A3. Та же домашка глазами наблюдателя (`scope = all`)

Понедельник, слот 2 — две строки подряд с тегами:
```
2. Информатика — каб. 1058 [Тех]
   📝 ...
2. Обществознание — каб. 3021 [Соц.-эконом.]
   📝 ...
```
Среда, слот 3:
```
3. Английский — каб. 4005 [Белова]
   📝 ...
3. Английский — библ [Петрова]
   📝 ...
```
Правило: одинаковый урок (один `scheduleId`), два текста → склейка через пустую строку
без тегов; разные аудитории → соседние строки с тегами. Теги видны всегда.

### A4. Общая домашка (главный сценарий)

Ученик `tech` пишет ДЗ по `Биологии` → ученик `soc` открывает завтра и видит
`3. Биология — 📝 <тот же текст>`. Один `scheduleId` → одна домашка на всех.
Профильное не пересекается: ДЗ по `Информатика [Тех]` ученик `soc` не видит вообще
(у него в этот слот другой урок).

### A5. Запись домашки

- Режим «моё»: как раньше — ввёл предмет → бот нашёл ближайший урок **твоего** профиля →
  ввёл текст → готово.
- Режим «всё»: если предмету соответствует >1 вариант — уточнение кнопками:
  `Информатика: [Тех] [Соц]` → дальше как обычно. Если вариант один — без вопросов.

### A6. Вкладка `/profile` (всегда доступна, меняется когда угодно)

```
👤 Ваш профиль
🏫 Класс: 10А
🧬 Профиль: Технологический
👩‍🏫 Английский: Белова
👁 Режим: Моё / Всё
[🏫 Изменить класс] [🧬 Изменить профиль] [👩‍🏫 Изменить учителя]
[👁 Переключить: Всё] [🔄 Сбросить] [🔙 Меню]
```
«Изменить» открывает только нужный шаг; «Сбросить» стирает профиль (следующий клик —
онбординг заново).

### A7. Мастер ВЫКЛ (состояние прода сейчас и «аварийный» режим)

Никого ни о чём не спрашивают. Все видят merged-view как в A3 (весь 10А, с тегами).
Запись — как в OLD. Отличие от OLD только косметическое: новое меню админки.

### A8. Админ (ты)

`⚙️ Управление`: `📚 Управление уроками` (добавить/править/смотреть/удалить/звонки),
`🧩 Режимы` (мастер-флаг + режим домашки), `📊 Пользователи` (ID, профиль, lastSeen,
последние действия), `📈 Статистика`. Кнопок каталога (Классы/Профили/Подгруппы) в меню
**нет** — каталог правится в `config/audience.json` по SSH.

## B. НА ДЕЛЕ — что происходит в данных и коде (по тем же сценариям)

- **B-A1:** `Setting(multiprofile_enabled)=1` → `lazyOnboarding` не находит `UserProfile` →
  `selectProfile`. Классов включённых = 1 → шаг класса скипнут (`classId='10А'` молча).
  Выбор трека/подгруппы из `Track`/`Subgroup` (`active=1`). Финал:
  `UserProfile.upsert(userId, 10А, tech, belova, scope='own', version=1)` + денорма в `User`.
  «Видеть всё» → `UserProfile(userId, 10А, null, null, scope='all')`.
- **B-A2:** `getHomeworkForDate(userId, Пн)` → профиль → `getScheduleForDay(0, профиль)`:
  `WHERE classId='10А' AND (trackId IS NULL OR 'tech') AND (subgroupId IS NULL OR 'belova')`.
  Домашка: `WHERE scheduleId IN (...) AND date` (+ `userId`, если `personal`).
- **B-A3:** профиль `scope='all'` → тот же запрос без track/subgroup-фильтров (только класс);
  рендер группирует по `(day, lesson)`, теги из `TAG_TEMPLATE`.
- **B-A4:** общий урок = один `scheduleId` → одна строка `Homework(scheduleId, date)`,
  видимая всем предикатам. Профильные `scheduleId` disjoint → пересечений нет по построению.
- **B-A5:** `findNextLesson(предмет, дата, профиль)`; при `scope='all'` и >1 совпадения —
  disambiguation-кнопки с `scheduleId`.
- **B-A6:** `UserProfile` чтение/частичный `enter(selectProfile, {edit})`/`destroy`; тоггл scope —
  `update(scope)`.
- **B-A7:** флага нет/`0` → все ветки `enabled=false` → запросы без аудитории; merged-рендер
  тот же код, что B-A3.
- **B-A8:** каталог читается из `config/audience.json` → upsert справочников; кнопки каталога
  скрыты; `Пользователи` — `User` + `UserEvent` (телеметрия с каждого апдейта).

## C. Чеклист приёмки (definition of done)

**Тестовый стенд (флаг ВКЛ):**
- [ ] Новый юзер проходит A1 за ≤4 клика; повторный вход — сразу меню, вопросов нет.
- [ ] `tech/belova` и `soc/petrova` видят свои варианты Пн-2/Ср-3 и общие уроки (A2).
- [ ] Наблюдатель видит обе строки с тегами (A3); теги есть всегда, даже в OFF.
- [ ] Биология, записанная tech, видна soc (A4); Информатика tech не видна soc.
- [ ] Запись в `all` с двумя вариантами спрашивает уточнение (A5).
- [ ] `/profile`: смена каждого поля, тоггл Моё/Всё, сброс → онбординг заново (A6).

- [ ] Админка: уроки/режимы/пользователи работают; кнопок каталога нет (A8).
- [ ] Boot без `❌`; `sync` на пустой и боевой БД даёт одинаковую схему; counts до/после.
- [ ] Лимиты: merged-неделя с тегами укладывается в чанкинг 4096.

## C1. Ручной смоук по живому тестовому боту (P5, шаги для человека)

Гонять только на тестовом стенде с включённым флагом, с двух-трёх живых аккаунтов
(один tech+Белова, один soc+Петрова, один наблюдатель). Прод не трогать.

Онбординг: новым аккаунтом отправить старт — вместо меню сразу выбор профиля
(шага класса нет, 10А подставлен молча). Выбрать Технологический, затем Белова —
должны прийти подтверждение сохранения и главное меню, сверху строка профиля
10А, Технологический, Белова. Повторный старт — сразу меню, вопросов нет.
Отдельным аккаунтом на первом же шаге нажать Видеть всё — онбординг завершается
сразу, дальше виден весь класс.

Запись: своим аккаунтом tech добавить ДЗ по Биологии — бот находит ближайший
урок твоего профиля без лишних вопросов, текст сохраняется. Наблюдателем
добавить ДЗ по Информатике — бот спрашивает уточнение кнопками Тех или Соц,
после выбора сохраняет в нужный вариант.

Показ: завтра у tech видны только свои уроки (Биология, Информатика-тех,
английский Беловой) и общие; обществознания и английского Петровой нет.
У soc — зеркально. Наблюдатель в тот же день видит обе строки подряд с тегами
Тех и Соц.-эконом., в среду — оба английских с тегами Белова и Петрова.
Биология, записанная tech, видна у soc тем же текстом; Информатика tech у soc
не видна вообще.

Профиль: открыть вкладку Профиль — видны класс, профиль, учитель, режим.
По очереди сменить профиль, учителя, класс — карточка обновляется. Переключить
режим на Всё и обратно на Моё. Нажать Сбросить — профиль стёрт, следующий клик
снова ведёт в онбординг.

Мастер ВЫКЛ: выключить флаг на стенде — все аккаунты без вопросов видят склейку
всего 10А с тегами, запись работает как раньше. Включить обратно — каждый снова
видит своё, новичка спрашивают профиль.

Админка: открыть Управление — разделы Уроки, Режимы, Пользователи, Статистика
открываются и работают; кнопок каталога Классы, Профили, Подгруппы в меню нет.
В Пользователях виден тестовый юзер с профилем и последними действиями.

Чанкинг: открыть неделю с длинными текстами и тегами — приходит несколько
сообщений подряд, обрывов нет, последнее с кнопкой возврата в меню.

## D. Лог UI-фиксов (6 пунктов, только UI-слой)

- **F1. Средняя кнопка учителя убрана.** `src/scenes/selectProfileScene.js`, `buildSubgroupKeyboard`: удалён ряд `Без группы/Все` (`select_subgroup:null`). Остались `[Белова] [Петрова] [👀 Видеть всё]` + отмена. Почему: меньше вариантов (Hick's law), «без группы» дублировал «видеть всё». Обработка `select_subgroup:null` в коде оставлена (старые сообщения). Фолбэк `Без группы` в карточке профиля не тронут.
- **F2. Тупик отмены в selectProfile закрыт.** `src/scenes/selectProfileScene.js` (шаги 1–4): все 4 `ctx.reply(CANCEL_MSG)` дополнены клавиатурой `👤 Выбрать профиль (profile) + 🔙 Вернуться в меню (back_to_menu)`. Почему: голая отмена без кнопок — тупик; оба колбэка глобально зарегистрированы (`profile` → handleProfile, `back_to_menu` → handleBackToMenu), зацикливания нет (сцена покидается в той же ветке).
- **F3. Бэки users/stats ведут в админку.** `src/scenes/helpers/manageScheduleHelpers.js`: в `handleUsersList` (список, пагинация, пустые страницы), `handleUserDetail` (деталка, обе кнопки, ошибки) и `handleStats` кнопки `schedule_back`/`backKeyboard` заменены на `admin_back`/`adminBackKeyboard`. Почему: `schedule_back` ведёт в подменю уроков — неверное назначение для пользователей/статистики. В уроковых флоу (`add/edit/delete/bells`) `schedule_back` оставлен как было.
- **F4. Единый выход в меню.** Новый `src/utils/navigation.js` — `leaveToMenu(ctx)`: `answerCbQuery` + `scene.leave()` (если в сцене) + показ главного меню через `handleStart` (ленивый require, без циклов). Используется в 3 ветках `back_to_menu` сцены `manageSchedule` (`src/scenes/manageScheduleScene.js`, шаги 1–3; в шаге 3 ветка `back_to_menu` отделена от `schedule_cancel`, пара «Действие отменено + leave» заменена на `leaveToMenu` без второго сообщения). Add-сцены не тронуты — там паттерн уже верный.
- **F5. Ввод даты в истории.** `src/utils/historyDate.js` (новый `parseHistoryDateInput`: `ДД.ММ`, день 1–31, месяц 1–12, год текущий, несуществующие даты отклоняются, при ошибке — `HISTORY_BAD_DATE` → переспрос) + `src/handlers/commands.js` (`historyNavKeyboard` — кнопка `📅 Ввести дату`; `handleHistoryDate` — промпт + флаг `session.pendingHistoryDate`; `handleHistoryDateInput` — парс и компактный вид одного дня через `getHistoryForRange(date, date)` + `formatHistoryCompact`) + `src/index.js` (`history_date` action и `bot.on('text')` вне сцен). Скоуп/visibility — как у остальной истории (внутри `getHistoryForRange`).
- **F6. Этот раздел.** Зафиксировано здесь: что, где, почему — по 6 пунктам, коротко.
